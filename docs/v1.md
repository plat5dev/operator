# First slice

Get a request through. No authz beyond "is this an operator?", no module host, no changes to plat5 or Auth.

`accounts/`, `gateway/`, and `console/` are this slice.

## Pieces

| Piece | Does | Does not |
|-------|------|----------|
| Accounts | Operator directory. Login issues a bearer token. Logout revokes it. Password change revokes outstanding tokens and issues a new one. The browser session is that token in an httpOnly cookie. | Plat5 Auth. Customer `user_id`. Roles. Signup. |
| Gateway | Validates the bearer or the session cookie. Own route list to existing service URLs. Injects the declared target. Strips the operator credential. Writes the attribution log. | Customer gateway. etcd. route-registry. Actor headers. |
| Console | Login, account settings, logout. Empty service menu. | A customer page. Naming a target. Calling a route. Direct calls to services or to the customer gateway. |

The route list is this gateway's config: path, upstream address, which target headers the route requires. Upstream addresses are copied from the deployment. They are not discovered from the customer route map. Configured routes are under `/api`. Other page paths are the console.

Token shape (JWT or opaque) is an implementation choice. The contract is a bearer token the gateway can validate, which the upstream never sees. Login still returns that token for a non-browser client. The console does not read it.

## The hole

Any authenticated operator may name any target and call any route on this gateway. That is accepted until RBAC is actually required. Do not add a role column, an allow-all policy, or a `TODO` check in the request path to look ready.

## Not in this slice

- RBAC
- A console module per customer API
- Creating customer logins
- An identity call the target user is not allowed to make
- One shared route source with the customer route-registry

Ready conditions for those are in [`AGENTS.md`](../AGENTS.md). They are not implied features.
