# First slice

Get a request through. No authz beyond "is this an operator?", no remote module loader, no changes to plat5 or Auth.

`accounts/`, `gateway/`, `console/`, and the default identity module are this slice.

## Pieces

| Piece | Does | Does not |
|-------|------|----------|
| Accounts | Operator directory. Login issues a bearer token. Logout revokes it. Password change revokes outstanding tokens and issues a new one. The browser session is that token in an httpOnly cookie. | Plat5 Auth. Customer `user_id`. Roles. Signup. |
| Gateway | Validates the bearer or the session cookie. Own route list of identity URLs. Strips the operator credential. Forwards the path. Writes the attribution log. | Customer gateway. etcd. route-registry. Actor headers. |
| Console | Login, account settings, logout. Loads every module in the modules file the same way. | A module the shell names. A page from another origin. Direct calls to services or to the customer gateway. |

The route list is this gateway's config: path and upstream address. Paths are identity's URLs. The path names the target. Upstream addresses are copied from the deployment. They are not discovered from the customer route map. Module pages are the console. Module files are not routes. See [`modules.md`](modules.md).

Token shape (JWT or opaque) is an implementation choice. The contract is a bearer token the gateway can validate, which the upstream never sees. Login still returns that token for a non-browser client. The console does not read it.

## The hole

Any authenticated operator may name any target and call any route on this gateway. That is accepted until RBAC is actually required. Do not add a role column, an allow-all policy, or a `TODO` check in the request path to look ready.

## Not in this slice

- RBAC
- Creating customer logins
- One shared route source with the customer route-registry

Ready conditions for those are in [`AGENTS.md`](../AGENTS.md). They are not implied features.
